# robotforge Goal

## North star

robotforge 的目标是成为轻量、打开快、质感好、可自由探索和创造的机器人仿真器。
用户能用自然语言或直接操控设计、组合和体验机器人，也能打开外部 URDF 和网格。
整体仿真材质与视觉质量、快速加载、流畅交互和可玩性共同决定产品体验，面向 macOS 和 Windows。
完整方案见 [OVERVIEW.md](OVERVIEW.md)。

## 当前长期目标（2026-10-23）

在保持轻量化和快速加载的情况下，持续提升整个项目的仿真材质质量与可玩性。
优先选择能覆盖多类机器人、物体、场景和地形的通用改进，让用户更容易开始操作、探索、组合和创造。
框架维护服务于这些体验目标，后续工作按体验收益和实测成本排序。
举铁、开抽屉等单项动作的成功率优化暂缓，不作为当前开发主线。

- 整体质感：改善共享材质、光照、阴影、表面细节和尺度感，让不同场景与资产的观感一致，运动与接触容易看清。
- 轻量体验：复用资源、按需加载并管理渲染开销，保留小安装体积、快冷启动、快场景切换和流畅交互。
- 可玩性：打通开箱体验、直接操控、自由组合、场景交互、快速重置和短挑战，使已有能力容易发现、反复尝试和扩展。

验收以真实应用的同场景前后对照为准，同时记录安装与资源体积、首次可交互耗时、冷暖加载耗时、帧率和内存。
现有 [性能预算](bench/budget.json) 继续作为约束，先测当前基线再提出具体改进目标，不能通过自动放宽预算来宣称提升。
每个阶段保留可观看的场景实录，并说明观感或玩法的收益及其性能成本。
已有物理、执行、接口和实验回归继续作为质量护栏，按改动范围验证。
当前实施顺序见 [ROADMAP.md](ROADMAP.md)。

## 既有产品理念

用户在 2026-10-14 重申的理念，每一轮都要对照：

- 任意创建机器人：模板只是起点，还要能用零件自由拼装，也能导入外部模型。
- 多场景：桌面、厨房、仓库、公园、迷宫这类开箱即用的场景，以及一句话生成场景。
- 多地形：平地、草地、坡道、台阶、起伏地形、障碍物。
- 多种算法适配：经典控制、逆运动学、MPC、强化学习、脚本，统一的环境接口，同一个机器人可以换算法对比。
- 新手第一：每个能力都要有一句话就能用的入口，和看得懂的解释。

用户在 2026-10-18 调整了重心：中心不完全放在教学，轻量、灵活、创造、全面（完整的机器人技术链条，传感器、感知、建图定位、规划、控制、学习）同等重要。
教学是每个能力的入口之一，不再是主线。
阶段 G 起的 milestone 和工作流见 [ROADMAP.md](ROADMAP.md)。

## Mode

Evolving。
下面的 Floor 是第一阶段的地板，不是终点。
地板全部真实验证通过后，进入 Frontier 阶梯，持续抬高标准，直到用户叫停或遇到 Gate。

## Floor：MVP 验收（每条都要真实运行验证）

| ID | 验收项 | 怎么验证 |
|---|---|---|
| A1 | “给我一只四足狗，让它在草地上走” | 真实 agent 会话（`claude -p` 或 `codex exec` 挂载本插件）完成；仿真中 10 秒内机身前进超过 1 米且不摔倒；查看器截图 |
| A2 | “做一个机械臂，把红方块放进盒子” | 真实 agent 会话完成；agent 写的 `behaviors/*.py` 运行后方块质心落在盒子内；查看器截图 |
| A3 | 丢进一个外部 URDF 文件夹 | 至少 3 个真实公开 URDF（含 `package://` 路径和 DAE 网格的）诊断修复后能加载；滑条和键盘可控 |
| A4 | “给我一台 Go2” | 从机器人库加载；键盘遥控能站立并移动 |
| A5 | 查看器 | 本地网页可用；Claude Desktop 对话内嵌可用，或记录清楚为什么不行并提供退回方案 |
| A6 | 双客户端 | Claude Code 和 Codex 都能挂载插件并完成 A1 |
| A7 | 轻量化 | 实测并记录：核心安装体积、冷启动到看到机器人的时间、重编译时间、查看器帧率 |
| A8 | Windows | GitHub Actions 的 Windows runner 上测试和无头冒烟测试通过 |
| A9 | 工程质量 | `ruff check` 干净，`pytest` 全绿，核心逻辑（编译器、导入诊断、模板、工具处理）有测试 |

## Frontier 阶梯（地板之后，按 ambition x feasibility 排序，每轮可重排）

阶段 G 起按 docs/ROADMAP.md 推进（轻量、灵活、创造、全面四条主线）。
阶段 A 到 F 的可玩性与教学规划见 docs/PLAY_PLAN.md。

0. 理念必备项（与地板并行推进）：人形机器人、零件自由拼装、多场景、多地形、算法适配层（Gym 风格环境接口、采样式 MPC、经典控制、强化学习）。
1. 自定义形态的强化学习：CPU 训练基准，然后让用户设计的四足学会走路。
2. 学习路线：内置任务线和教学口吻的 Skill，新手从挥手走到训练策略。
3. 评测集：约 15 个机器人需求，Claude 和 GPT 自动跑分对比。
4. 一键安装：Claude Desktop 的 .mcpb 包，冷启动体验打磨。
5. 传感器套件：相机、深度、激光雷达、IMU、触觉的读数和查看器曲线。
6. 分享：MuJoCo WASM 静态页面，导出一段仿真或一个策略。
7. CAD 扩展：build123d 精确零件，导出 STEP 和打印文件。
8. sim2real：和 LeRobot SO-100 等真实硬件打通。
9. 远程部署：接入 ChatGPT 和 claude.ai 网页版。

## 预先批准的依赖

运行时：mujoco、numpy、mcp（官方 Python SDK）、pydantic、pyyaml、manifold3d、trimesh、mink、robot_descriptions、coacd、websockets 或 starlette 加 uvicorn（二选一，取更轻的）、Pillow。
前端：three.js（vendored ES module，不引入前端构建链）。
开发：pytest、ruff。
扩展（可选 extra，后期）：build123d。
强化学习（用户 2026-10-14 批准“sb3 + unilab”）：
- 可选 extra `rl`：gymnasium、stable-baselines3、PyTorch（CPU 版）。核心安装不包含。
- 可选 extra `policy`：onnxruntime，用来在 robotforge 里回放 UniLab 等外部训练出的 ONNX 策略。
- UniLab 作为外部训练后端，放在独立的 checkout 和虚拟环境里，通过命令行调用；不进入 robotforge 的依赖（它锁定 torch 2.7 和 mujoco-uni 3.8，与本项目的 mujoco 冲突）。

超出这个列表的新依赖属于 Gate。

## Gates：暂停并询问用户

- 引入上面列表以外的依赖，或启用新的 MCP server。
- 新增 MCP 工具：用户 2026-10-18 同意，不必再问；保持少而精，能挂在现有工具上的就不新开，每个新工具都要写进 agent 说明和技能并有测试。
- 仓库改为公开、发布到 PyPI、发布 .mcpb 或任何对外发布与部署。
- 宣布 world.yaml 或 MCP 工具接口为稳定版之后的不兼容修改。
- 任何花钱的操作、删除用户数据、修改安全或凭据策略。

推送到私有仓库 origin 的 main 分支属于日常 RECORD 的一部分，用户已在建立仓库时授权。

## 每轮协议

遵循全局 CLAUDE.md 的 Autonomous Loop：ORIENT（冷启动，读 GOAL、STATUS、progress、git log）、PLAN、EXECUTE、VERIFY（真实运行并观察）、RECORD（提交、推送、覆盖 STATUS 和 progress、写 heartbeat）。
重型任务（完整测试、仿真批量、浏览器验证）串行执行，用完即关。
