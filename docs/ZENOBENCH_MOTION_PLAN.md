# 计划：在 Mac 上替代 ZenoBench 的 cuRobo 规划器

状态：2026-10-29 确认，规划库用 OMPL 2.0.1；按阶段实施。

## 为什么要做

- 移植现在固定在 `d573467`（10-26），用的是 ZenoBench 旧的手写规划器。
- 上游 main 已到 `914d2a2`（10-28），比固定版本多 25 个提交，改了 95 个文件。
- 从 `4fd4ae5` 起，手臂的 IK、碰撞检测、关节规划全部交给 cuRobo 0.7.8，上游写明"没有别的求解器"。
- cuRobo 只能跑在 CUDA 上：0.7.8 是 PyTorch + CUDA，4 月发布的 v0.8（cuRoboV2）是重写，仍然基于 CUDA 和 Warp，而且 API 不兼容，ZenoBench 也没用它。
- 所以要跟上上游，Mac 上必须有一个自己的实现来顶替 `zeno_skills/motion.py` 里的 `Motion` 类。

## 接口有多大

`Motion` 是唯一的接入点，上游其他代码只通过它调用 cuRobo。

- 创建：`runtime.make_rig` 里 `kin.motion = Motion(stage, ann)`，`tools/build_tasks.py` 做可达性检查时也会创建。
- `ArmKin` 转发 8 个调用：`ik`、`cart_path`、`free`、`segment_free`、`plan`、`plan_to`、`clearance`、`penetration`。
- `Rig` 调用 `sync`、`release_held`，并读写 `held_collision`；`skills.py` 用 `part_at` 检查开关门这类会带动部件的动作。
- `run_episode` 把 `motion.STATS` 写进报告；`tests/test_held_collision.py` 引用 `box_spheres`、`add_held_links` 等工具函数。
- `motion.py` 只在函数内部 import cuRobo，所以模块本身在 Mac 上能正常 import。
- 做法：照旧导入上游模块，只把 `Motion` 换成我们的类，工具函数、常量和 `STATS` 都用上游原样的。
- ZenoBench 的其他代码一行不改，和现在的移植方式一致。

## 方案

### 1. 规划用的碰撞世界：复用 MuJoCo 物理模型

- 从物理模型复制一份规划模型，世界里的碰撞体和机器人在仿真里实际撞到的完全一样：带 PhysX 顶点上限的凸包，静态三角网格是 CoACD 拆出的凸块。
- 机器人自己的碰撞体在规划模型里关掉，换成上游 `zeno_malo.yml` 里的 283 个球（27 个连杆，由 Isaac 的生成器按 PhysX 碰撞体拟合），另外每只手预留 32 个球给手里的物体。
- 用球而不用机器人的真实凸包，是为了和上游规划器一样保守：微波炉腔体这种只差几毫米的地方，判断结果要和 cuRobo 一致。
- 用 contype/conaffinity 位掩码只让"机器人球对世界"成对检测，再由 `mj_collision` 一次算出所有距离。
- 自碰撞按 yml 的 `self_collision_ignore` 列出球对，用 numpy 计算。
- 实测（T07 厨房，10,211 个碰撞体）：单核每次检测 71 微秒，8 线程每秒 84,000 次（MuJoCo 计算时释放 GIL）。
- `sync` 从物理数据复制物体和部件的位姿；`part_at` 临时改一个部件的关节值，退出时恢复。

### 2. 照搬上游的碰撞语义，每条一个单元测试

- 碰撞余量 5 毫米（`ACTIVATION`）；`clearance` 最多量到 5 厘米；`penetration` 取最深穿透。
- 手里的物体和它装着的东西，对拿着它的那只手不算障碍；另一只手离它 5 厘米以内时也不算（交接）。
- TCP 目标点落在某个物体的包围盒加 3 厘米内时，这个物体不算障碍（正要抓或推的物体）。
- `ignore_fingers` 关掉手指的球，`hand_touches_part` 再关掉夹爪和腕部相机的球。
- 查询时另一只手臂锁住；它的手指和正在接触世界的连杆不参与检测。
- 搬运阶段（`held_collision`）把手中物体的包围盒填成球挂到 TCP 上；物体还碰着东西时先不挂。
- 离底座 2.5 米以外的障碍关掉（`CULL`），与上游保持一致。
- 关节上下限取 `kin.lo` / `kin.hi`，被钉住的关节放宽 ±1 毫米，和上游一样。

### 3. IK 和直线路径

- 用 `ArmKin` 的 URDF 链（上游保留的精确 FK）写一个按批计算的 FK 和雅可比，对 9 个关节（升降、腰、7 个手臂关节）一次解 32 个种子，用 Levenberg-Marquardt。
- 精度和上游一样：位置 4 毫米、姿态 0.04 rad。
- 顺序和上游一样：先只算运动学；解碰撞时，先在批里找无碰撞的解，再用接触法向沿零空间把手臂推开，最后加随机种子重试。
- 选解直接照抄上游的打分：离种子近、离关节限位至少 0.15 rad、可操作度高；`local` 模式不换分支。
- `cart_path` 按上游的步长逐点求 IK，相邻两点每个关节最多变化 0.25 rad，再按 0.05 rad 的间隔检查关节空间里的每一段。

### 4. 关节空间规划

- 先试直线，不行再用 RRT-Connect 在 9 维关节空间里搜，底座和另一只手臂固定。
- 搜到后做捷径化和 B 样条平滑，每一步都重新检测碰撞，让路径像 cuRobo 轨迹优化的结果一样顺。
- 预算和上游一致：最多 5 次尝试，8 秒超时。
- 只需要输出关节路点：`Rig.follow` 自己会把路点加密并按 60% 速度上限重新定时，所以不用做时间参数化。
- 规划库有两个选择，见下面的"需要你决定"。

### 5. 带约束的两种腿

- `plan_to`（不是搬运）：上游让轨迹前半段自由绕开障碍，后半段沿目标坐标系的一根轴直线进入。
- 我们拆成两步：先自由规划到预进入位姿（目标沿那根轴后退半段），再走一段姿态不变的直线；腿不沿任何轴时直接失败，和上游一样。
- 搬运时保持倾角：规划过程中把每个新状态投影回"倾角不变"（2 行雅可比的 Gauss-Newton，即 CBiRRT 的做法），最后检查最大倾角不超过 0.15 rad。

### 6. 上游的其他改动（一起升级固定版本）

- `pad_torsion` 给指垫加了扭转摩擦：在转换器里映射成 MuJoCo 的扭转摩擦，并测一下捏着瓶子时它还会不会绕捏合轴转。
- 粘手模式（sticky hands）运行时增删 PhysX 固定关节：在 shim 里用预分配的 weld 约束开关实现；它只用于 GT/开发配置，正式 benchmark 用的是物理抓取，可以排在后面。
- 场景、标注改了一批（含 LFS），要重新拉取并重建凸包缓存；`benchmark/protocol.py` 等是纯 Python，不需要改。

## 分阶段

每个阶段都在真实场景里验证，通过后用 `scripts/land.py` 合进 main 并推送。

1. **P0 升级骨架**：固定版本改到上游 head，先放一个一调用就报错的 `Motion`，跑一个 T07 回合，确认只剩规划器这一处缺口；同时移植 `pad_torsion`。
2. **P1 碰撞世界**：规划模型、`free` / `segment_free` / `clearance` / `penetration` / `sync` / `part_at` / 搬运球，加单元测试；检查球心 FK 和 `ArmKin` 的 FK 误差小于 1 毫米。
3. **P2 IK 和 `cart_path`**：批量 LM、碰撞修复、打分；用记录下来的真实回合查询测成功率和耗时。
4. **P3 规划**：`plan` 和 `plan_to`，含平滑和倾角约束；T07 种子 0 的微波炉那段要能规划出来。
5. **P4 全量对比**：60 条路线、21 个探针、35 个场景 × 5 种子的 sweep，加上 T07、P06（上游说它们在种子 10 上能过），并录并排对比视频，写进 `docs/ZENOBENCH.md`。
6. **P5（可选）逐次查询对照**：在你的 NVIDIA 电脑上跑上游的 cuRobo，把每次 `Motion` 查询的输入和结果录下来，拿到 Mac 上回放，统计两边的判断一致率。

## 怎么算完成

- 上游代码不改，`robotforge zenobench` 在上游 head 上能完整跑完所有回合，不需要 CUDA。
- T07 微波炉那段能规划出来；T07 和 P06 在种子 10 上能过。
- 路线数和 sweep 的成功数不低于旧版本（43/60，平均 22.4/35），低于的地方要写清原因。
- 每个回合的规划总耗时打印在 `STATS` 里，目标是不超过整回合墙钟时间的 15%。

## 风险

- **没有 Isaac 基准**：上游的 `RESULTS.md` 是 cuRobo 之前的结果，cuRobo 之后只发布了"种子 10 上 6 个冒烟回合过了 5 个"。在上游重跑或我们做 P5 之前，新版本只能和旧版本、和这 6 个回合对比。
- **路径和 cuRobo 不同**：采样加平滑的路径和轨迹优化的结果不一样，执行时的接触也可能不同；P4 会逐条看失败原因，必要时调大余量。
- **IK 分支不同**：选到另一个分支，后面的动作就会不一样；照抄打分可以缩小差别，P5 能直接量出来。
- **CoACD 凸块和 PhysX 三角网格**：静态薄面在两边略有不同，腔体和书架的间隙可能差几毫米；P1 要专门测微波炉腔体和书架。
- **上游变化很快**：两天 25 个提交，所以每次只固定到一个提交，定期再升级。

## 需要你决定

- 规划库：
  - **OMPL 2.0.1**（推荐）：PyPI 上有 macOS arm64 的 cp312/cp313 wheel。RRT-Connect、路径简化和带投影的约束空间都现成可用，碰撞检测接我们的 MuJoCo 检查器。需要往 `zenobench` 可选依赖里加一个包。
  - **自己写**：大约 400 行 numpy 实现 RRT-Connect、捷径化和 CBiRRT 投影，不加依赖，边检测可以多线程并行，但这部分代码要我们自己维护。
- P5 要用你的 NVIDIA 电脑，到 P4 之后再问你。
