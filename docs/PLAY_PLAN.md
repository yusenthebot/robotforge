# 可玩性与入门教学规划

2026-10-15 起草，等用户确认顺序和几个决定后开工。
目标对应 docs/GOAL.md 的核心价值：最适合新手入门具身智能，任意造机器人，多场景多地形，多种算法（MPC、RL 等）。

## 现在的问题

- 教学和画面是断开的：9 节课只是给聊天 agent 的提示词，viewer 不知道你在上哪一课、做到哪一步、做对了没有。
- 打开 viewer 没有目标：能推、能 WASD、能换地图，但没有"要做成什么"，玩两分钟就没事可做。
- 原理看不见：机器人为什么倒、MPC 在想什么、RL 学到了什么，画面上都没有，只能听 agent 讲。
- 用户自己能做的事太少：除了 WASD 和滑块，"让它做任何事"必须回到聊天里。

## 核心思路

把 robotforge 从"带遥控器的查看器"变成"有关卡的机器人实验室"。
每件事都要有目标、有即时反馈、看得见原理、能对比、能自己改。
物理和判定仍然在 Python 里（权威），viewer 负责呈现和交互，聊天 agent 读同一份状态来当导师。

## 阶段一：新手的第一个小时（先做，直接解决"做不到入门教学"）

- 任务引擎 `src/robotforge/missions/`：一个任务 = 场景 + 机器人 + 目标检查 + 星级标准 + 提示 + 讲解卡。
  检查在物理里算：到达区域、保持站立 N 秒、方块进盒子、用时、摔倒次数、耗能。
- viewer 任务界面：顶部目标条（目标、进度、计时、星星），分步教练（等你真的做了某个动作才进入下一步，比如真的推了一下、真的切到了 MPC），完成页（为什么成功的讲解卡 + 下一关）。
- 第 0 章"十分钟上手"，5 关：推一下机器狗看它站稳，换一张地图，用 WASD 走到旗子，切到 MPC 站稳再推它对比，用滑块让机械臂碰到小球。
- 把现有 9 节课改成任务形式（第 1 到 3 章：关节与执行器、轮式与步态、IK 与抓放、传感器、PD/LQR/MPC、写脚本、训练策略），在 viewer 里能独立完成，agent 仍然可以陪着讲。
- 关卡地图：章节、星星、解锁顺序，进度存在本地。
- agent 接口：新增 MCP 工具 `missions`、`start_mission`、`mission_status`，让 Claude/GPT 知道你卡在哪一步，按需讲解。

## 阶段二：看见原理（透视层，教学的核心）

- 平衡：重心投影和支撑多边形，重心一出多边形就会倒，倒之前变红。
- 接触与力：脚底接触点、推力箭头、关节力矩热度。
- MPC：画出它每 20 毫秒预演的几十条未来轨迹（灰色），和最后选中的那条（琥珀色）。
- RL：观测和动作的实时条形图，看策略在"看什么、做什么"。
- 传感器：机器人摄像头画中画、激光雷达射线、IMU 倾角表。
- 实时曲线：速度、倾角、耗能、奖励。
- 每个透视开关都配一句"这说明什么"，任务里在需要的时候自动打开。

## 阶段三：可玩性（挑战与对比）

- 挑战模式：障碍赛道和迷宫计时赛，推不倒挑战（推力逐级加大，看能扛几级），限时搬运，台阶高度递增的爬坡赛。
- 本地排行榜和幽灵回放：和自己上一次、和别的控制器比。
- 对比实验台：同一个机器人、同一块地形、同样的推力，两种控制器并排跑（手写步态、RL、MPPI），最后出一张结果表。
- 调参台：PD 增益、MPC 样本数和预测时长、步频，拖动立刻看到效果和曲线，比如增益调太大会抖。

## 阶段四：自己造、自己教

- 训练你的机器人：一键开始训练，viewer 里看奖励曲线和每一代的走姿回放，从乱爬到会走。
  小机器人用 ARS 或 PPO 在 CPU 上几分钟见效，用现有的 SB3 栈。
- 工坊：viewer 里直接拼装（腿数、腿长、电机、轮子），改完立刻拿去跑一关，形成"造、测、改"的循环。
- 行为卡片：不写代码也能编排"走到 A、抓起方块、放到 B"，背后生成脚本，进阶用户可以看和改 Python。
- 进度与分享：成就、作品集，导出世界和回放文件。

## 为什么是这个顺序

- 阶段一直接解决入门问题，而且任务引擎是后面所有东西的骨架（挑战、对比、训练都是"带检查的任务"）。
- 阶段二是教学的灵魂，任务里的讲解卡要靠它"指给你看"。
- 阶段三提供重玩价值，阶段四把天花板拉到"自己造、自己教"。

## 验收（每阶段都要真跑）

- 每个任务都有脚本化的"标准解法"测试：用对的方法必须过关，用错的方法必须失败，星级判定可复现。
- 在浏览器里真实通关第 0 章，不打开聊天，10 分钟内完成。
- 透视层每个开关截图核对：画的东西和物理数据一致（重心、接触、MPC 轨迹）。
- 现有 440 个测试和 smoke 保持全绿，Windows CI 通过。

## 需要用户决定

1. 顺序是否按阶段一到四。
2. 新增 MCP 工具（任务相关）属于公开接口变更，需要同意。
3. 教学是否以"不开聊天也能学"为准（推荐），聊天 agent 作为加分项。
4. 游戏化程度：星级、排行榜、成就要不要，做到什么程度。
5. 行为卡片：自己做简单卡片界面（推荐，无新依赖），还是引入 Blockly（新前端依赖，需要同意）。

## 第二版（2026-10-15，用户反馈后）

用户反馈：真实机器人（G1 人形、Piper 机械臂）要和我们自己的模板对比；课程除了倒立摆那课，其他都要大幅提升；控制器调参和强化学习训练要能调参并且看出区别；地形还有闪烁。

### 诊断

- 倒立摆那课清楚，是因为它有一眼可见的“失败到成功”的转变，一个动作对应一个看得见的结果，还有一条会讲故事的曲线。
- PID 课的曲线会滚走，改参数前后没法对比；IK 课是二连杆玩具，离真实机器人太远；传感器课是一串“开一米、转一圈”的任务，没有“为什么需要这个传感器”的冲突。
- 调参只有一条实时曲线，旧结果会被冲掉；强化学习课没有可调的超参数。
- 闪烁：已修三处（地面与地形的深度冲突、地形接缝、远处纹理闪烁），静帧中复现不到用户看到的情况，需要用户指出场景。

### 方向

把 robotforge 从“若干独立的演示课”变成“机器人实验台”：任何机器人、任何控制器或算法，都能调参、并排运行、叠加曲线对比。
课程是实验台上的引导路线，最后一步落到真实机器人（Piper、G1、Go2）上。

### 阶段 A：真实机器人和稳定性

- 加入 AgileX Piper（MuJoCo Menagerie 有官方模型），检查 G1 和 Piper 在查看器、行为、IK、抓放中都可用。
- 对比功能：模板机器人和真实机器人并排，规格卡（关节数、质量、臂展或身高、电机力矩），同一任务对比（机械臂：够目标的精度和时间、抓放成功率；人形：站立抗推、姿态）。
- 闪烁：按用户指出的场景复现并修到底。

### 阶段 B：调参能看出区别（实验台核心）

- 运行记录：每次运行自动保存参数、曲线和指标；最多 5 次叠加在同一张图里，配指标表（超调、稳定时间、耗能；训练得分、用时）。
- 并排双胞胎：同一场景放 2 到 3 个相同的机器人，用不同参数同时运行。
- 参数扫描：一个参数自动扫一遍，画出“指标随参数变化”的曲线，看见权衡。
- 覆盖 PID、LQR（Q 和 R 权重）、MPC（预测时长、采样数、噪声）、步态（步频、抬腿高度）、强化学习（ARS 的步长、噪声、方向数，奖励权重；可选 PPO）。

### 阶段 C：按倒立摆课的标准重做课程

- 统一结构：先看到问题，一次只动一个旋钮，先猜再试，双胞胎对比和曲线叠加，公式里填上实时数字，挑战，迁移到真实机器人。
- PID：三个增益并排加扫描图，最后在 Piper 的一个关节上调。
- IK：换成 Piper 六轴：三维拖动目标、雅可比迭代、可操作度椭球和奇异点，和我们的机械臂比工作空间。
- 传感器：改成“用激光雷达写一个不撞墙的自动驾驶”，调阈值看效果；加噪声滑条，展示里程计漂移被激光雷达纠正。
- 新课：步态（相位、摆动与支撑、步频调参），人形平衡（重心和支撑多边形，和 G1 对比）。

### 阶段 D：前沿

- 训练用户自己拼的机器人走路（自定义形态的强化学习），在查看器里看训练过程。
- 训练能走完障碍赛道的地形策略。
- 让 Claude 或 GPT 读取课程进度来当导师（新增 MCP 工具，需要用户同意）。
- “新手试玩代理”在浏览器里自动玩每一课并报告卡住的地方，作为课程质量的评测。

### 待用户决定

1. 用 UniLab 训练 G1 走路策略（约占用机器 2 小时）。

3. 新增课程相关的 MCP 工具。
