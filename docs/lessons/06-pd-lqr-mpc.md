# 第 6 课 控制算法：PD、LQR 和 MPC 比一比

目标：用三种控制器让倒立摆保持平衡，扛住中途的一推，并读懂一张对比表。

## 你可以这样说

> 做一个倒立摆，分别用 PD、LQR 和 MPC 让它保持平衡，中途推它一下，比较哪个最好。

## 你会看到

agent 放一个倒立摆：一辆在轨道上滑的小车，车上立着一根没有电机的杆子。
它先用 LQR 实时控制，第 2 秒时猛推杆子一下，杆子晃一晃又站稳了。
然后在后台把四种做法各跑一遍，给出一张表（作者电脑上的结果）：

| 方法 | 得分 | 成功 | 结束时杆子角度 | 用力（焦耳） | 算力（秒/仿真秒） |
|---|---|---|---|---|---|
| none（不控制） | -13.04 | 否 | 117 度 | 0.00 | 0.01 |
| pd | 11.38 | 是 | 0.45 度 | 0.70 | 0.02 |
| lqr | 11.72 | 是 | 0.34 度 | 1.02 | 0.04 |
| mpc | 11.48 | 是 | 0.54 度 | 2.20 | 0.14 |

## 背后的道理

反馈控制就是：量出误差，往反方向推。
PD 控制：误差越大推得越用力（P，比例），误差变化越快越要刹车（D，微分），规则是凭直觉写的。
LQR 先把杆子竖直附近的物理“拉直”成线性方程，再根据你在乎什么（Q）和用力有多贵（R）直接算出最好的增益，增益是算出来的，不是调出来的。
MPC 每 20 毫秒把未来零点几秒模拟几十遍，挑最好的那一个执行，什么机器人都能用，但计算量最大，表里它的算力一栏最高。
不控制（none）的杆子两秒多就倒了，这说明平衡完全是控制器的功劳。

## 自己动手

让 agent 调一调 LQR：`method_params={"q_weights": [5, 50, 0.5, 1], "r_weight": 0.5}`，看看用力和角度怎么变。
给 MPC 少一点样本（`{"mpc": {"samples": 16}}`），看看它还稳不稳。
问 agent：为什么 MPC 用的力最多？

## 怎么算成功

LQR 实时运行被推之后 `success` 仍然是 true。
对比表里 none 失败、其他三种成功，agent 的解释和表里的数字对得上。

## 挑战

换一个更长的杆子（`update_robot` 改 `pole_length`），重新对比，看看哪种方法最先撑不住。
