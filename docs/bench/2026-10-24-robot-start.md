# 机器人起点与自建路线实测（2026-10-24，第73轮）

本轮改善自由搭建与重玩：在“机器人”面板选择“设置起点／朝向”，旋转后点地面或固定台面，即可保存现有机器人的起点并暂停。
保留模板、名字、传感器、挂载与其它配置，重置、布局保存和恢复使用新起点。
支持一次撤销，恢复目标机器人原来的配置、关节／控制与手动模式。
整体材质、轻量体验与可玩性目标继续，单项动作成功率仍暂缓。

## 行为与边界

只编辑 world 中明确拥有的顶层机器人，挂载组件随整机移动，子组件没有独立入口。
服务端验证版本、代次、世界哈希、干燥地面或固定水平台面，检查整个 home 占地、保存位置与最新实时障碍，并拒绝搬走正在支撑其它物体的机器人。
目标回到新 home 并暂停，其它机器人保留 qpos／ctrl 和可保留的传感器／感知估计，沿用既有编辑后速度与时间归零语义。
提取既有布局 XML／YAML／历史安装器，保留真正存档的两次记录校验；失败恢复磁盘与内存，恢复失败则暂停并要求重开。
这是进程内受保护发布，不声明多文件崩溃原子性或旧运行控制器连续性。
自定义活动钩子、跨所有者约束、匿名状态、mocap／flex 等不在此编辑契约内。
旧接口保留，新增 robot_edit 查看器元数据，没有新增 MCP 工具、依赖、贴图或常驻绘制 pass。
朝向标记只在编辑时绘制。

## 验证结果

- 1326 项针对性默认测试、198 项完整 browser 测试、8 项 GPU 资产／传感器测试通过，共1532项不同用例，其中54项新增。
- 一项默认测试因缺少可选 policy extra 跳过，未运行完整默认套件。
- 七项既有框架基线、源码与全新离线锁定 wheel 的 CLI／查看器／60工具 MCP 冒烟通过。
- Ruff、格式、24个JavaScript语法检查与395个包内源码文件逐字节比对通过。
- 624项生产／测试／脚本输入从正式测试前冻结，后续保持不变；119项外部 helper／动态 support／fixture 最终校验相符。
- 五个冻结场景各480个模型数组的shape／dtype／字节、标量、展开网格与物理状态一致。
- 22张固定视角PNG像素、投影、绘制调用和资源数一致，旧scene字段全部相同，只排除新增robot_edit字段。
- 三个视角的eye／target有最大4.44e-15浮点残差，均小于预先使用的1e-10对照容差，不声明相机逐位一致。
- 270项最终证据检查通过，Python、UI源码与验收方法独立复核通过。

## 实际视频

所有编辑、驾驶、撤销、暂停、重置、保存与恢复操作均由真实Chrome原生输入触发，直接后端暂停／重置和相机准备只发生在录制前。
两段rover完整路线各有首次与网页重载后重玩，每次保留至少五个不同物理时间的真实正接触力样本。
附加lidar及机器人其它配置保留，新起点为(0,-1.2)、朝向90度；重置回到该home，布局字节校验与新解释器重开复制件得到同样world和home qpos。
新解释器中的暂停由辅助程序主动设置，不是暂停状态持久化证明。

## 保留失败与可追溯性

开发期测试曾有错误关节名、两次不存在测试路径、WebSocket二进制读取，以及录屏驱动误等第二次确认；修正驱动或fixture后通过，原始开发日志保留。
正式原生实录v1/v2/v3分别因屏幕外点、五次滚轮不足、逐位相机稳定等待超时而失败，完整失败manifest／traceback／原始帧保留。
v1的stdout路径被v2驱动误覆盖，恢复文本来自原manifest，不声称原stdout字节完整保留。
v4录屏通过：只在实际目标不在画布时使用原生Fit／有界滚轮，工作流相邻相机分量以1e-9稳定八个RAF；固定截图另用1e-12稳定并保留未舍入的实际视角对照。
新进程辅助程序先后有错误import与遗漏required session两次失败，v6修正为现有构造方式；原日志和失败复制件保留，未重录已通过的视频或重跑正式测试。
“最终选定阶段通过”不表示所有尝试通过；原预算只执行一次。
