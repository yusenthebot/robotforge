# Malo 接入、真实模型入口和共享光照（2026-10-27）

本轮把用户已有的 Zeno Malo EDU 描述包接入本地工作区，并让真实模型与保存设计能在查看器中直接选择和放置。
轻量、共享画质和创造玩法目标继续；未调整单项抓取或举铁成功率。
使用说明见 [MALO.md](../MALO.md)。

## 已实现

- 从本地 generated URDF 加载 Malo，保存可复用设计；建立 Malo 工作区、Go2 仓库、Panda 工作台三个独立世界。
- 查看器提供 Go2、Panda 和本地设计卡片；列目录不编译或下载，首次选择库模型才允许下载。
- 添加按版本、generation 和原文件校验，检查落点、台面与占用，保护原机器人状态和失败回滚；已有添加/撤销接口保持兼容。
- 增加通用独立转向控制器，保留源轮速、转向角和力矩限制；转向先对齐，停止立即清零轮速目标。
- pitch/roll 轮腿、摇臂悬挂和滑动悬挂继续使用既有驱动/平衡与导入摩擦策略；存在倾斜或混合转向的未知结构明确拒绝。
- 原有 `drive_to` 二维动作任务拒绝独立转向机器人，不改变任务动作维数；普通移动、脚本和导航另行实际验证。
- 查看器增加可选日光，默认摄影棚数值保留；复用环境与阴影资源，不重涂 Malo 或修改原生 PBR。
- 光照偏好保存在本地浏览器。RGB、双目、鱼眼、事件相机预览固定使用摄影棚光照，模拟物理及传感器配置不变。

Malo 网格继续引用用户本地描述包，未进入 Git 或安装包。软件 Apache 许可不替代 CAD 原所有者条款。
保留源白/灰 RGBA 和 `respect_effort_limits=True`；未定义未经验证的 TCP、IK 或高层抓取端点。
头部 RGB 是附加的理想化模拟相机，不是实机双目标定复现。

## 视觉与成本

正式摄影棚/日光配对使用同一最终源码，均在暂停、重置后拍摄。
Malo、Go2、Panda 三个世界已记录的 qpos、eye/target、几何/纹理数量、绘制调用、三角形数保持一致，GL 与页面错误为空；未核对完整投影矩阵。
这证明增加了一种共享显示选择及其资源边界，不是 main 到候选的全画面逐像素无回归或普遍更好看的证明。
原先不同开发源码的 before/daylight 画面只保留作预览，不纳入正式配对。

原方法安装/查看器预算只运行一次，11/11 通过，没有放宽阈值：

| 项目 | 实测 |
| --- | ---: |
| wheel | 3,872,149 B，比上一运行基线增加 11,477 B |
| 核心锁定安装 | 163.4326 MB，42 个包 |
| 锁定依赖下载量 | 52.5149 MB |
| 标准场景冷启动首帧 | 0.5535 s |
| 仓库查看器 | 60.1009 FPS，2.6 ms 绘制 |
| 资产组合查看器 | 60.253 FPS，3.5 ms 绘制 |
| 标准狗场景服务峰值内存 | 133.5 MB |
| 标准狗场景空闲 CPU | 3.8% 单核 |

这些标准预算不是 Malo 的冷导入承诺。
Malo 源 STL 约 35.9 MB，一台 Malo 工作区的网格二进制响应约 47.1 MB，在本地按需加载。
正式配对的已有转换缓存下，编译、启动 Chrome 到可交互约 1.37–1.51 秒；不是全新 CAD 转换或远程下载的冷测。
同组 Go2/Panda 已缓存工作区约 1.39–1.66 秒和 1.11–1.23 秒。
三世界的 RAF 中位间隔约 16.7 ms，不把它当作 GPU 同步绘制耗时。
