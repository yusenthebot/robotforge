## 产品行为与真实回归

选中已有道具后新增“查看”：根据当前渲染几何的完整包围范围取景，包含桌子等多部件物体，以及已运动自由物体的实时位置。

查看不修改布局、仿真时间、播放状态、qpos、qvel 或控制输入。Escape 退出选择，“看全部”返回全景。原移动、复制、移除与 API 保持兼容。

整套浏览器检查暴露课程打开的真实时序回归：首次姿态消息安排了稳定后的第二次取景，较晚返回的 `lesson_open` 响应再次打开课程时把它清掉。
手机 PID 场景的第三台机器人右边界因此落在约 410.557 px，超过 390 px 窗口；等待四秒仍没有补偿取景。
修复在这个已收到姿态的分支重新安排原有延迟取景，保留底盘稳定等待和手动镜头取消规则，没有调整控制器或课程物理参数。
新增测试截留真实响应并按这个顺序释放，同时验证自动取景、手动触摸优先两条路径，保留严格屏幕边界断言。

复制叠放失败来自测试投影点取在相机尚未稳定时；改为等待真实渲染帧数值稳定，再计算点击坐标，原有 3 mm 位置断言保留。
创建卡片可被真实 `robot_info` 刷新替换，可信点击监听改为检查当前 DOM 节点，仍是一次原生点击，未增加重试或自动放置。
静止相机每帧有约 1e-15 的浮点残差，不能用 JSON 字符串完全相等判断静止；驱动以 1e-9 数值容差、连续八帧和有界超时检测。
手动镜头回归容差为 1e-7，相对实际相机阻尼尾差约 2.9e-9；另有独立方向检查，防止恢复预设镜头却误判通过。

## 材质与阴影筛选

在 Malo、Go2、Panda 三个固定世界，各录普通距离和近景，比较原画面、4096 阴影图、降低三块环境补光强度的候选。
世界 YAML 与非视觉数值数组保持一致；每世界采集 486 项数组。Malo 仅缓存目录字符串与地址不同，实际引用的同一 STL 文件哈希相同；Go2/Panda 所有数组完全相同。
相机最大数值残差小于 4e-14，投影、裁剪距离一致；保留原始相机值，没有靠四舍五入掩盖不同取景。

4096 图在近处改善部分阴影边缘，普通画面平均 RGB 绝对变化仅约 0.005、0.063、0.007（8 bit）。四倍像素的资源代价缺乏足够普通视距收益，因此拒绝。
仅按 RGBA8 颜色附件计算，2048→4096 的理论增量约 48 MiB，尚未计深度；未测实际 GPU 分配，资源对象数量相同不等于字节成本相同。
降低三块补光主要使整体变暗，普通距离平均 RGB 变化约 13.68、11.31、11.11，没有明确材质质量收益，同样拒绝。
两项实验都只在外部源码快照运行；本次产品没有采用新阴影图、环境强度、贴图、着色 pass 或依赖。不能把筛选过程当作已交付的材质提升。
