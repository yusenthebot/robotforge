# 道具排成一行（2026-11-01）

状态：本机代码、实际操作、严格对照、预算与六段录像验收通过；GitHub 交付另行核对。

暂停后按顺序选择 2–16 件独立直立道具，指定 0.05–2 米边缘间距，再用完整轮廓预览排成一行。
保留每件道具原有朝向，再用既有旋转按钮调整整行；提交沿用整组搬移事务和一次整组撤销。
源头须在保存和实际姿态中共同落在同一外部水平支撑上，堆叠、外部承载、任务引用、占用及陈旧状态继续受既有保护。
这项功能服务桌面整理与障碍组合，不模拟机器人搬运路径，也不调整任何单项动作成功率。

## 接口与兼容

现有 `prepare_object_group` 仅增加显式 `mode="move", layout="row", gap=...` 选项。
省略新字段仍使用原复制默认；`layout="preserve"` 的旧响应不增加字段。
行模式保留源 `pos/yaw/geoms/offset`，另返回服务器拥有的 `target_offset`，提交仍使用原 token、版本、代次、摘要、落点及朝向。
客户端不能覆盖目标偏移；准备期间改变间距、选择或指针状态，会阻止过期回复打开预览。
准备后再改间距会取消预览，重置或场景变化继续撤销旧资格。
完整箱壁、桌腿与实体圆形轮廓参与间距及目标检查，预览借用原几何且不释放源缓冲区。

## 已保留的问题及修正

- 初期 25 项既有组合插入测试失败暴露共享变换函数的鸭子类型调用；将行模式限定到 `PreparedGroup` 后，同一组 192 项通过。
- 第一轮相关浏览器的两项 320px 用例真实失败。原生截图和命中栈证明编辑提示盖住道具列表；条件样式让选择时的场景面板高于编辑面板，保持尺寸、滚动及输入逻辑不变。
- 旧单物界面固定将坐标保留四位小数，不能达到旋转后整行成员的完整精度坐标。原始失败保留；修订验收分别核对真实逐件操作和独立精确 API 对照，不放宽像素相等规则。
- 首份 Go2 布置在源码复核中发现一角进入原坡道。旧方案未获通过；新实验只将整行落点从 `[1.8,-2.7,0]` 改为 `[1.5,-2.7,0]`，保留原世界、坡道、添加道具、相机、间距、朝向、顺序及拒绝点。完整实际实体占地前置证明必须通过。
- Malo 固定箱旋转使编译器重排匿名几何，并从世界坐标网格改为刚体局部网格。旧全局序号对照失败，后续另行冻结已接受源码的精确局部表示参考；碰撞部件与其余网格仍逐项核对。共享网格实例再以所属物体、刚体、资源及几何分组建立完整一一对应，重复键立即失败。
- 早期 Malo 逐件对照完成四次真实操作及全部姿态／物理／参考检查，但 Chrome 交付的 551 帧中有一次约 16.7ms 时间倒序。全部 551 帧和确认均保留，录像仍计为失败；后续方案另行审查执行，没有排序或删除旧帧来冒充通过。
- 后续另行声明逐次原生截图采样方案，最高 10Hz，保留所有返回 JPEG、原始响应、采集时段和输入时段；它不证明连续高帧率或每一瞬态。第一次方案中的请求编号竞争在执行前被审查拒绝；修正后的运行保留 37 帧，在首次选择点击未送达时失败，具体原因未被追溯证明。再以互斥方式隔开完整输入与截图，保留输入／重载造成的采样间隙。

## 体积与加载观察

wheel 为 4,148,897 B，比已接受版本增加 3,432 B；仍在原 4 MiB 上限内，余量 45,407 B。
锁定安装保留 42 个包、164.066 MB 安装占用和 52.515 MB 下载体积，没有新增资源或依赖。
真实原场景的全部 HTTP 响应均完成且没有失败：Malo 48,523,093→48,527,269 B，Go2 21,790,933→21,795,109 B。
两者各 34 个请求，均增加 4,176 B（包含传输头）；四个对应观察阶段的绘制统计、纹理／几何内存计数与着色器数量一致。

固定 ABBA 原始查看器测量全部通过原预算；普通场景约 60 FPS。
其冷启动为对照 0.572／0.563 秒、候选 0.937／0.926 秒，不能声称启动加速。
测量后发现对照树含 363 个源码字节码缓存，候选树为零；禁止写入缓存并不禁止读取既有缓存。
独立补充诊断以四个空字节码目录执行同一冷启动路径，保留四次原始启动和原有排除首轮、取其余最小值的规则。
固定 ABBA 为对照 1.3753 秒、候选 1.3704／1.3658 秒、对照 1.3594 秒，中位数分别约 1.3674／1.3681 秒，仅差约 0.7ms。
全部源码、原缓存字节／时间、保护树与原测量保持不变，四个新缓存目录始终为空。
这支持原差异对缓存状态敏感的判断，不证明全部因果、普遍性能等价或功能加速；全局 Python 缓存政策也影响依赖，补充诊断不替换原测量与原预算。
