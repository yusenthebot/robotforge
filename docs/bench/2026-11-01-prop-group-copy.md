# 整组复制道具与场景复用（2026-11-01）

暂停后，在“场景与搭建”的现有道具中选择一组，通过场景点击或名称列表选取 2–16 个直立刚体道具，再整体旋转、放置一份独立副本。
工作台连同桌上收纳盒、标记物，以及上下堆叠的箱子，都保留原有相对位置、高度、朝向、尺寸、颜色、材质、质量、固定状态和其他作者参数。
复制结果仍是可独立编辑的普通道具；支持最新一次整组撤销，没有增加焊接组合、组合库、连续复制或整组移动／删除。
原有单物操作、消息字段和默认行为保留，没有调整单项动作成功率、材质着色或机器人控制。

## 一次提交与运行边界

新增 `prepare_object_group` 和 `duplicate_object_group` 查看器消息，由服务器保存短期准备结果与姿态摘要，校验版本、重置代数、世界文件和实时姿态。
完整预览借用当前可见几何的只读缓冲，包括桌腿和收纳盒侧壁；隐藏碰撞体不阻塞预览，预览清理不释放原始几何。
提交成功后，前端等待所有副本的场景描述、姿态、实际绘制、状态和版本／代数一致，才开放整组撤销；显示超时保留仍有效的撤销收据。

一次成功的整组复制为 **1 次 `compile_world` 管线、2 次既有 native 编译阶段、1 次模型安装、1 次版本递增**。
既有编译器在生成 home key 前后分别编译，本轮没有将两个 native 阶段合并，也不把它称为一次 native 编译。
对照中原有单物复制每件含准备共 2 管线、4 native 阶段、1 次模型安装；MALO 三件首轮由 6／12／3 降为 1／2／1，Go2 两件由 4／8／2 降为 1／2／1。
这些是结构性计数，不是普遍延迟加速结论；被占位置拒绝仍有 1 管线、2 native 阶段，模型安装为零。

源道具必须直立、完整支撑，所选支撑关系图的最底层根支撑位于同一水平高度；目标根部必须完整落在同一水平支撑拥有者上。
支撑认证覆盖水平 plane／box／cylinder 的真实面，桌子的四条腿全部检查，不用包围盒或单个碰撞接触代替完整支撑。
倾斜、缺失支撑、部分悬空、不同根高度、占用及不支持的编辑环境会明确拒绝。
撤销也检查副本上是否新增了外部承载物；失败不会消费有效准备，可在同一准备下换空地重试。

`WorldStore.apply` 仅增加可选的内部编译后校验与文件变更收据，原有调用路径保留。
运行安装失败时只恢复确实属于该事务的世界／构建／历史变更；外部修改、删除、替换目录或符号链接不会被覆盖或补回。
无法确认权威世界时使相关编辑收据失效，避免在未知状态继续编辑。

## 能力信息更新的轻量修复

两次旧源码正式预算的空闲 CPU 分别为 6.2% 与 6.6%，超过原 6% 上限，其余十项通过；两次失败均保留，没有提高阈值。
原方法 ABBA 中基线与旧候选均跨越 6%，未证明稳定的候选特有退化。
低侵入计时发现每秒能力回调重复解析同一世界三次，首五秒 15 次读取共 17.44 ms，占该窗 326.3 ms CPU 的一小部分。
现改为单次回调共用一次保存世界快照，课程机器人的描述仍用课程世界，任务契约仍用保存世界；不跨回调缓存。
外部 YAML／插件刷新、无保存世界的模型发现、模型替换保护、独立消息副本及复制失败重试均保持，插件读取在仿真锁之外。
实际修改后首窗 5 次回调对应 5 次读取，约 5.39 ms；一次原方法正式预算空闲 CPU 4.8%，十一项全部通过。
不同运行存在波动，重复解析的减少不能单独解释总体 CPU 差异，不宣称普遍提速；物理、控制器与广播频率未变。

## 失败保留与范围

开发期 NumPy／MuJoCo 枚举比较暴露球体、圆柱体支撑分类问题，现已显式使用整数类型，完整测试覆盖。
独立 Python 审查发现运行安装失败时外部世界和历史目录可能被回滚覆盖，修复并补充回归；Python 和 UI 审查通过；最终能力快照增量另经独立 Python 审查通过。
首次 Ruff 的两处格式问题修正后重新冻结 v2，早期中断的默认套件与其 teardown 错误不记为通过。
初次 Go2 测试箱与原 dock 重叠、错误的“一 native 编译”计数假设、被工具栏挡住的验证点击，以及旧基线 Chrome 的 headless 标注错误均有独立更正记录，产品保护未放宽。
原生录像的资源复核进一步发现旧 ghost 在新世界首帧重新上传已释放源几何；三轮回归的 warmed 基线为 9 个几何，撤销后却累积为 14／19／24。
在释放世界前先解除预览及全部借用引用，并在加载期间阻止重建；保留提交 session 和完成等待。
同一回归先失败、修复后通过，整组浏览器文件 6 项通过；最终 v4 重新冻结并重跑正式检查和两条原生操作录像，旧 v2 不能作为最终无泄漏证据；v3 的两次 CPU 超限后又冻结 v4，最终媒体与检查绑定 v4 源。
原始场景比较最初要求两次独立运行的瞬时 `packObserved` 同值，MALO 两个 front 采样不满足；八对画面与传感器画布、资源、GL 状态和绑定恢复均一致。
独立复核确认该值不适合作跨运行同值门禁；修正比较器逐对保留原值，并明确要求各自恢复原绑定和三个 GL 错误均为零，不改变像素／模型／材质／相机或预算标准。
没有确定采样差异的具体调度原因，也没有据此修改产品或重录；原失败、旧脚本、修正说明与新回执全部保留。
只有明确标为最终的通过记录参与验收；失败日志、原始辅助脚本和更正说明留存。

本轮没有给既有材质／灯光筛选追加未经验证的画质收益；之前未达门槛的 dirt 和光向候选仍不进入产品。
支持范围为暂停、可编辑、直立刚体场景；Windows、真实手机、长期物理承载和机器人任务成功率未在本轮认证。
原始证据位于仓库外 `../robotforge-evidence/2026-10-31-prop-group-copy/`，机器摘要见同目录日期的 JSON 报告。
整体材质质量、轻量化和自由创作目标继续 active，后续继续以普通视距的共享视觉收益和低成本创作流程为主，不恢复单项动作成功率调参。
